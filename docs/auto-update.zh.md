# 自动更新（委托模式：检测 → 提示 → 交给安装器执行）

> 状态：**设计稿，未实现**
> 目标读者：改 `src/common`（检查与升级）、`src/tui`（确认框）、`.github/workflows/release.yml`（产物）的人
> 修订：
> - v1：完整自替换（程序自己下载、解包、改写可执行文件）
> - **v2（本稿）**：改为**委托模式** —— 程序只负责"判断有没有新版本"和"发起升级"，
>   实际的下载、校验、落盘交给已有的安装器 `tools/install.sh`。

## 0. 已定决策

| 决策 | 取值 | 对设计的影响 |
|---|---|---|
| 升级方式 | **委托给安装器** | 不需要 gzip 依赖、不需要 tar 解析、不需要改写自身二进制 |
| 检查频率 | **每次启动一次**，不周期 | 不需要 `last_check` 持久化、不需要周期服务、不需要 ETag |
| 签名 | **必须**，缺失即拒绝 | 验签由安装器执行（阶段 0 已落地） |
| 默认开关 | `update_check: true` | 首次运行必须告知（§10） |
| 更新后 | **提示，不自动重启** | 升级完成后用户自行重启 |
| Windows | 委托模式下受限 | 见 §8.4 |

## 1. 为什么是委托而不是自替换

v1 的设计是程序自己完成全部动作：下载归档、解 gzip、解 tar、原子替换可执行文件。它需要：

- 新增 zlib 依赖（仓库当前没有 gzip 能力）
- 一个最小 tar 读取器
- 三套替换原语（Linux/macOS 的 `rename`、Windows 的改名 + `.old` 清理）
- 在 Windows 上无法本地验证的代码路径

而这些动作，**安装器已经完整实现了**：`tools/install.sh` 会解析最新版本、挑平台资产、验签、校验和、`mv` 到目标目录。它的验签逻辑（阶段 0）比"程序自己实现一遍"更成熟，因为它是唯一一处需要维护的校验实现。

委托模式把职责切成两半：

| 谁 | 负责 |
|---|---|
| **程序** | 判断"有没有新版本"、告诉用户、在用户确认后调用安装器 |
| **安装器** | 下载、验签、校验和、落盘、报告结果 |

代价与收益：

| | 自替换（v1） | 委托（本稿） |
|---|---|---|
| 新增依赖 | zlib | 无 |
| 新增模块 | `edc_targz` + `edc_selfreplace` | 一个 `edc_upgrade` |
| 改写自身二进制 | 是 | 否 |
| 需要 shell | 否 | 是（POSIX sh + curl/wget + tar） |
| Windows | 支持（需改名逻辑） | 受限（见 §8.4） |
| 失败时的状态 | 可能留下半替换的二进制 | 安装器原子 `mv`，失败即保留旧版 |

## 2. 目标与非目标

**目标**：用户在 TUI 里收到「新版本可用」，确认一次，安装器在后台完成升级，提示重启。

**非目标**：

- 不支持降级。
- 不在 `dev`/`dirty` 构建上提示更新。
- 不静默升级——每次都要用户确认。
- 不自动重启。
- 不在没有 shell 的环境里假装能升级（§8.4 明确怎么做）。

## 3. 信任链

委托模式下信任链有**两段**，必须分别说清楚。

### 3.1 归档本身：签名校验（已实现）

安装器对每个归档做两道检查，顺序不可颠倒：

```
1. 下载 sha256sums.txt 与 sha256sums.txt.sig
2. 用内嵌公钥验签 sums.txt      ← 先验签
3. 从(已验证的) sums 取期望 sha256
4. 下载归档，比对该期望值        ← 后校验
```

先比校验和再验签，等于放行"同时修改产物和校验和"的攻击者。两条失败路径都是致命的，**没有跳过开关**。

| 手段 | 防得住 | 防不住 |
|---|---|---|
| 只有 TLS | 被动监听 | 发布流水线被入侵 |
| 校验和 | 传输损坏、拿错平台 | 同时改产物与校验和 |
| **校验和 + 签名** | 以上全部 | 签名私钥泄露 |

### 3.2 安装器脚本本身：钉在目标 tag 上

这是委托模式相对自替换**唯一变弱的地方**，必须写明。

程序要让安装器去装某个版本，就不能执行一个可被随意替换的脚本。做法：

```
取 https://raw.githubusercontent.com/<owner>/<repo>/<tag>/tools/install.sh
                    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 钉在要安装的那个 tag
```

而不是取 `master` 分支上的同名文件。

- **钉 tag 的意义**：脚本与它要安装的归档来自**同一次发布**。攻击者若想用篡改过的脚本绕过验签，必须同时篡改那个 tag 下的内容——与直接篡改仓库等价。
- **仍然存在的边界**：脚本自身没有签名。所以委托模式的信任锚是"TLS 到 GitHub + 该 tag 的内容未被篡改"，而自替换模式可以做到"归档有独立签名"。这个差异写进 `limitations.md`。
- **不做的事**：不执行任何未钉版本的位置（不取 `master`、不取 `latest`）。

## 4. 状态机

```
        ┌──────────┐  启动后延迟 10s，只一次
        │   IDLE   │────────────────────────────┐
        └──────────┘                            ▼
             ▲                            ┌───────────┐
             │  失败/超时/不适用           │ CHECKING  │
             │                            └─────┬─────┘
             │                      有更新可用   │   无更新/失败
             │                                  ▼
             │                            ┌───────────┐
             └────────────────────────────│  NOTIFIED │ 横幅（非模态）
                                          └─────┬─────┘
                                        用户确认
                                                ▼
                                          ┌───────────┐  取消
                                          │ CONFIRMING│──────────► IDLE
                                          └─────┬─────┘
                                             确认
                                                ▼
                                          ┌───────────┐
                                          │ UPGRADING │  安装器子进程，可取消
                                          └─────┬─────┘
                                      失败      │      成功
                                        ▼       ▼
                                  ┌────────┐ ┌──────────┐
                                  │ FAILED │ │ RESTART  │ 提示重启
                                  └────────┘ └──────────┘
```

`UPGRADING` 期间不做任何本地文件操作——所有写盘都由安装器完成，程序只读它的退出码与 stderr。

## 6. 检查（每次启动一次）

**端点**：`GET https://api.github.com/repos/<owner>/<repo>/releases`

不用 `/releases/latest`：它会跳过 prerelease，而本项目当前所有 tag 都带后缀。

**传输**：复用 `edc_https_client`（已支持重定向）。该端点不重定向，所以检查功能不依赖重定向支持。

**时序**：

```
启动 → TUI 首屏可交互 → 延迟 10s → 检查一次 → 结果 Post 给 UI（此后本进程不再查）
```

**护栏**：

- 超时 10s
- 失败静默（只有 `log_debug`），绝不产生用户可见噪音
- 不重试
- 结果只在本进程内存里，不落盘

**选择逻辑**（已实现于 `edc_update_pick`）：

```
候选 = releases 里 draft=false 的项
若 update_channel == "stable"：只取 prerelease=false
若 update_channel == "pre"   ：全部
取 semver 最大者，且必须 > 当前版本，且必须带本平台资产（归档 + sums + sig）
```

**当前版本**取自 `edc_version()`。若等于 `dev`/`unknown` 或含 `dirty`，整条链路禁用（§12）。

## 7. 探测安装方式

升级要交给"当初把它装进来的那个东西"，所以先问：**它是怎么装进来的？**

### 7.1 判定

只认一种情况，其余一律"未知"：

| 条件 | 判定 |
|---|---|
| 可执行文件位于 `$HOME/.local/bin/` **或** `$HOME/bin/`，且同目录有 `edgeclaw` | `installer` |
| 其他任何位置 | `unknown` |

判成 `unknown` 时的行为见 §8.4（只提示手动命令，不尝试执行任何东西）。

**为什么只认这两条路径**：它们是 `tools/install.sh` 的默认目标（`$HOME/.local/bin`，`--dir` 可改但默认值如此）。判定越宽，误判的代价越大——误判成 `installer` 会在一个不该被改写的目录里跑安装器。

### 7.2 可执行文件路径

新增 `edc_platform_exe_path()`：

| 平台 | 手段 |
|---|---|
| Linux | `readlink("/proc/self/exe")` |
| macOS | `_NSGetExecutablePath()` + `realpath` |
| Windows | `GetModuleFileNameW(NULL, ...)` |

## 8. 委托升级

### 8.1 执行什么

```
1. 取 https://raw.githubusercontent.com/<owner>/<repo>/<tag>/tools/install.sh
2. 写入一个 0700 私有临时目录下的 install.sh
3. 执行 sh <临时路径>/install.sh --tag <目标版本> --dir <当前目录>
4. 删除临时目录
```

- 脚本内容取自 `<tag>` 而非任何移动分支（钉版本，见 §3.2）
- 落成**文件**而不是从 stdin 喂：stdin 必须留给 `/dev/null`（§8.2），否则安装器会去读 TUI 的终端
- `--tag` 显式传入，不依赖安装器自己判断最新版——程序已经判断过了，两处判断会导致提示的版本与实际安装的版本不一致
- `--dir` 传入当前二进制所在目录，保证升级落在同一位置

### 8.2 执行环境

**必须与 TUI 的终端隔离**，否则安装器的输出会踩进 TUI 的渲染，且它会尝试读 stdin。

| 项 | 取值 |
|---|---|
| stdin | `/dev/null` |
| stdout / stderr | 捕获（各有上限，例如 64 KiB），只用于失败时告诉用户 |
| 超时 | 120 s，超时即杀进程组 |
| 工作目录 | 临时目录（安装器不需要 cwd，但也不该继承 TUI 的） |
| 环境变量 | 继承，但**去掉** `EDGECLAW_MASTER_KEY`（安装器不需要它，没有理由传） |

**不继承终端**这一条要在代码里注释清楚原因：安装器会 `printf` 进度，而 TUI 正在渲染同一块终端。

### 8.3 结果处理

| 退出码 | 处理 |
|---|---|
| 0 | 显示「已更新到 `<版本>`，重启后生效」，**不自动重启** |
| 非 0 | 显示失败原因（取 stderr 尾部），给出手动命令 |

**升级成功后不验证 `--version`**：安装器自己会 `chmod` 并 `mv`，而二进制已被替换、当前进程仍在跑旧的映射。验证需要 `exec` 新文件，那是"重启"的范畴，本设计明确不做（§12）。

### 8.4 无法升级的情形

这些情况**只提示，不执行**：

| 情形 | 提示 |
|---|---|
| 安装位置不匹配（§7.1 判为 `unknown`） | 给出手动命令：`sh install.sh --tag <版本>` |
| 没有 `sh` | 同上 |
| 没有 `curl` / `wget` | 同上 |
| Windows | 同上（见下） |

**Windows 的限制要直说**：安装器是 POSIX `sh` 脚本，Windows 上没有可靠的 `sh` 环境（Git Bash 的路径语义与原生不同，`$HOME`/`/tmp` 都可能错位）。所以在 Windows 上委托模式**不予支持**，`/update` 只显示版本信息与下载页链接，由用户手动替换。

这不是遗漏，是取舍：让程序在 Windows 上执行一个 POSIX 脚本，比不给自动升级更容易出事。

### 8.5 回滚

**不存在。** 新版本一旦启动，数据库会向前迁移（`EDC_DB_VERSION` 单向前进），旧二进制拒绝打开迁移后的库。

UI 必须说清楚：**更新后无法回退**。

## 9. UI

现有的 Toast 是 1.4 秒自动消失的 chip，不够用——升级需要一次明确的确认。

| 阶段 | 呈现 |
|---|---|
| 发现新版本 | 顶部横幅（非模态）：`v1.0.1 可用 · /update 查看` |
| 确认框 | 模态：版本号、release notes 链接、**「数据库会向前迁移，之后无法降级」**、`[更新] [取消]` |
| 升级中 | 底栏进度：`升级中…`，`Esc` 可中止（中止即杀安装器进程组） |
| 成功 | 模态：`已更新到 v1.0.1 · 重启后生效`，`[关闭]`。不提供「立即重启」 |
| 失败 | 模态：原因 + 手动命令 + `[关闭]` |
| 不适用 | 模态：说明为什么（§8.4），附手动命令 |

**线程**：检查与升级都在 app 的 uv loop 上异步进行，结果通过 `IUiDispatcher::Post` 回到 UI 线程，绝不阻塞渲染。

## 10. 配置与持久化

```json
{
  "update_check": true,          // 新增，默认 true；false = 完全不联网检查
  "update_channel": "stable"     // 新增，默认 "stable"；"pre" 才收 prerelease
}
```

- `update_check=false` 时零网络。
- **首次运行必须告知**：`onboarded` 流程里加一句「EdgeClaw 会定期检查更新（可在 config.json 关掉）」。静默联网检查一个处理私人对话的工具是应该说明的。
- 注：交互式升级由用户动作触发，与 `update_check` 无关——关掉检查后 `/update` 仍可用，只是不再主动提示。这一点要在文档里写明，否则用户会以为关掉开关就连手动升级都没了。

## 11. 失败模式矩阵

| 场景 | 行为 |
|---|---|
| 离线 / DNS 失败 | 静默（只 `log_debug`），不提示 |
| 403 / 429 限流 | 静默，不重试 |
| 无匹配本平台资产 | 静默（不是错误：只是这次不发版这个平台） |
| releases JSON 畸形 | 静默 |
| 当前版本不可解析（`dev`） | 整个链路禁用 |
| 安装方式未知 | 提示里给手动命令，不执行 |
| 没有 `sh` / `curl` / `wget` | 同上 |
| 安装器超时（120 s） | 杀掉进程组，报「升级超时」，提示手动命令 |
| 安装器非 0 退出 | 显示 stderr 尾部 |
| 安装器验签失败 | 透传它的错误（它会明确说明是签名还是校验和） |
| 升级中被用户中止 | 杀掉进程组；已下载的临时文件由安装器自己的 trap 清理 |
| Windows | 只提示手动方式 |

**统一原则**：检查阶段的任何失败都不产生用户可见噪音；升级阶段的任何失败都必须说清楚并给出下一步。

## 12. 安全边界：明确不做的事

1. **不降级**。数据库单向迁移。
2. **不在 `dev`/`dirty` 构建上提示或升级**。
3. **不执行未钉版本的脚本**（不取 `master`、不取 `latest`）。
4. **不静默升级**。必须确认。
5. **不自动重启**。
6. **不在 Windows 上执行 POSIX 安装器**。
7. **不把 API key 或任何用户数据发给更新端点**。请求里只有 `User-Agent`。
8. **不因为检查失败影响启动**。
9. **不自己改写可执行文件**（这是从 v1 收敛到本稿的核心）。
