## 1. 为什么是"一个动词"，而不是"一批命令"

把模板做成 `/review`、`/commit` 这样的**顶层命令**，会让命令空间同时承担两种东西：

| | 谁定义 | 本质 | 触发后发生什么 |
|---|---|---|---|
| 内置 `/` 命令 | 程序（C） | **动词**，有子命令和状态 | 改会话 / 任务 / 沙箱状态 |
| prompt 模板 | 用户 | **纯文本宏** | 展开成一段文字交给调度器 |

混在一起的代价很具体：命名冲突（用户目录里一个 `session.md` 就顶掉 `/session`）、
语义不一致（同样是 `/xxx`，有的执行有的事、有的只是粘贴）、补全菜单混排两类东西、
优先级规则要写文档解释。本仓的 `/` 空间**已经**是一个带子命令的小 CLI
（`/session new|switch|list`、`/task fork|chain|join`），在这上面叠用户文本宏是最糟的混法。

**所以模板不能是命令名，只能是参数。** 内置命令集于是永不增长——
这一条现在是 §4 的不变式 1，并且有专门的测试钉它（§5）。

## 2. 现状核实与本次清理

### 2.1 命令分发入口（新分支插在这里）

`edc_commands_handler()`（`src/shell/edc_commands.c`）的顺序：

```
!cmd        → edc_local_shell_handle()
/ 开头      → edc_shell_handle_builtin()          /whoami /model /sandbox
            → /prompt                            ← 本次新增（严格匹配）
            → /task  →  /group  →  /session  →  /help
            → 未知命令：回一条 "**Unknown command**"
非 / 开头    → edc_shell_execute()
```

两个现成工具函数：`edc_commands_is_command()`（**严格**前缀：等于前缀，或前缀 + 空格，
所以 `/promptx` 不会被 `/prompt` 吞掉）与 `edc_commands_arg()`（取前缀之后的尾巴）。

### 2.2 复用：skills 的 front matter 解析

`src/kernel/context/edc_skills.c` 已有"markdown + YAML front matter → 结构体"的一套。
新模块沿用它**读文件、扫目录**的做法，但**没有**沿用它按每个 `:` 切分的解析（会把
`description: Review: focus on X` 切坏）——新模块按**第一个** `:` 切，见 §3.2。

### 2.3 已删除 ①：`--prompt <name>`

它曾经是"已承诺但没兑现"：解析（`edc_cmd_parse.c`）、AST、任务字段、setter、持久化、
回执、`/task status` 展示全都在，**但三个调用点全部传 `NULL` 当正文**
（`edc_commands.c` 的 `/task new` 与 `/task fork`、`edc_shell.c` 的 spawn 路径）：

```c
if (opts.prompt_name)
    edc_task_set_prompt(task, opts.prompt_name, NULL);   /* 正文永远是 NULL */
```

于是 `task->prompt` 永远是 NULL，消费点（"非空才用它顶替系统提示"）永远不走——
**唯一可见效果是回执里多印一个名字。**

处置：**整条链路删除**（`prompt_name` / `prompt` 字段、`edc_task_set_prompt`、三个调用点、
序列化、`/task fork --prompt` 的解析与展示、帮助文本、文档）。复用提示词现在是 `/prompt` 的职责。

副作用（**行为变化，已写进测试**）：`/task fork` 过去可以靠 `--prompt p1` 凑出第二个 token，
从而"没有 desc 也建任务"；现在**没有 desc 就是用法错误**。

### 2.4 已删除 ②：`edc_completion.c`

561 行，命令 trie + 前缀/模糊匹配 + 三个 source（commands / files / history），
编在 `//src/shell:completion` 里——**零调用者、无测试**；真正的输入框
（`src/tui/edc_input.cpp` 的 `EdcInput`）只有上/下历史召回，**没有任何 Tab 补全**。
所以"复用现成补全引擎"这句话不成立，它是死代码。

处置：**模块整体删除**（源文件、BUILD target、依赖、头文件、以及 `edc_cli_history.h`
里对它的引用）。补全将**单独重做**。

### 2.5 展开的落点

`edc_shell_execute(sm, sched, to, message)` 读 `message->content` 与 `message->session_id`，
依次做 `@` 判定 → 历史展开 → `edc_shell_tokenize()` → `ast_parse()` → `ast_execute()`。
给它一个带 `content` 的消息，就得到"和一整行 shell 输入完全一样"的行为。
消息可以现造：`edc_channel_message_new()`（它接管 content 的所有权，
`edc_channel_message_free()` 会释放）。

### 2.6 输入层已经有 `$` 阶段（记号归属问题）

`edc_shell_vars.c` 的 `$` 是**任务引用**（`$$` = 前台任务 id、`$N`/`$LAST`/`$NAME` = 任务输出），
`edc_shell_collect_var_refs()` 在**建任务时**跑一遍并把依赖挂上（引用不到=硬错误）。
**含义**：模板层如果也用 `$`，两个层级就会争同一个记号——§3.3 因此改用 `{{…}}`。

## 3. 方案（已实现）

### 3.1 命令面

```
/prompt                      列出模板：名字 · argument-hint · description
/prompt <name>               展开（无参数）
/prompt <name> <arg> <arg>…  展开（带参数）
```

**没有保留字**：不设 `list` / `help` 之类的子命令，所以叫 `list` 的模板不会被顶掉——
裸 `/prompt` 就是"列出"。名字不存在时回一条错误 + 指出目录，并提示跑 `/prompt` 看清单。

### 3.2 文件格式与位置

位置：**`<conf->workspace>/prompts/<name>.md`**（扁平，只收直接子级 `*.md`）。

- 与 skills 一致：**工作区级**，不是项目级（项目级留到"项目信任"那一期，见 §6）。
- 扁平而不是 `<name>/PROMPT.md`：skill 要目录是为了带附属脚本；模板只有一段文本，
  扁平 `.md` 让"文件名即名字"直接成立。
- 默认工作区是**内嵌**的（`BUILD` 的 `glob(["workspace/**"])` + `tools/embed_workspace.py`），
  所以 `workspace/prompts/` 不需要改任何构建文件。

```markdown
---
description: Review staged git changes
argument-hint: "[focus]"
---
Review the staged changes. Start by running `!git diff --staged` to see them.
Focus on {{1:-correctness, security, and error handling}}.
```

- `description` 进列表；`argument-hint` 也进列表。
- **front matter 可选**（偏离原设计，见 §7）：没有 front matter 时，
  `description` 取正文第一非空行（截断到 120 字节）。
- `description` / `argument-hint` 的值按**第一个** `:` 切分；值两端成对的引号会被去掉。
- front matter **开了 `---` 却没闭合** → 该文件被拒绝并 `log_warn`（不半解析）；
  正文为空 → 同样拒绝。一个坏文件不会打断列表。

### 3.3 参数替换规格

**切分参数**：空白 + 引号（`"…"` / `'…'`），`\` 转义下一个字节。
**不识别** `|` `;` `&` `>` ——它们是普通字节。理由：`/prompt` 的参数是"模板的输入"，
不是一行 shell；操作符应当由模板正文或参数文本本身产生（展开之后自然会被 §2.5 看见）。

**替换**（在正文上执行一遍）。**占位符是 `$…`** —— 与 pi / Claude Code / opencode **同一套写法**，
所以他们的模板/技能搬过来零改动；`{{…}}` 是同一套文法的**历史别名**，照样认：

| 写法 | 结果 |
|---|---|
| `$1` … `$N` | 第 N 个参数。**多位**（`$10` 是第 10 个，和 opencode 的 `/\$(\d+)/` 一致） |
| `${10}` | 第 N 个参数，**花括号形式支持多位** |
| `$@` / `$ARGUMENTS` | 全部参数，空格连接 |
| `${N:-D}` | 第 N 个参数，缺失或为空则用 `D` |
| `${@:-D}` | 全部参数，一个都没有则用 `D` |
| `${@:N}` / `${@:N:L}` | 从第 N 个参数起（1 基）/ 再取 L 个 |
| `{{1}}` `{{1:-D}}` `{{@:2:1}}` … | 历史别名，与上面一一对应 |
| `\$` | 一个字面 `$` |
| `$HOME` `$$` `$0` 落单的 `{` `{{weird}}` | **原样保留**（不是引用 → 用户输入会被追加，见下） |

**为什么现在可以放心用 `$`**：任务引用已经搬到 `{{…}}`（见顶部"变更"），两层各占一个记号、
互不干扰。旧的"`$` 在输入层有四个含义所以模板层不能用"这条理由，**已被这次换记号作废**。

- 这一层**没有转义**：想写字面 `{{1}}` 目前没有写法（实践中罕见——未识别形式原样保留，
  所以 `{{msg}}`、`{1}` 这类都是安全的）。
- 展开结果里如果出现 `$`，那是**正文里本来就有**的，归输入层解释（见 §3.4 的代价一条）。

### 3.4 展开的落点与边界

展开后的文本**不再进入命令分发**，而是当作**用户输入**：造一条临时消息 →
`edc_shell_execute()` → 释放。

- ✅ **天然防环**：正文里写 `/prompt` 也不会递归。
- ✅ **白拿 shell 能力**：正文可以是 `!git diff --staged | 帮我 review`——
  管道、`;`、`&`、重定向、`$` 全都能用（pi/opencode 的模板没有这层）。
- ✅ **语义干净**：模板 = 用户输入，命令 = 程序动词。
- ❌ **代价 1**：模板不能"调用另一个内置命令"。有意为之（§4 不变式 2），有测试钉。
- ❌ **代价 2（残留）**：正文里的 `$` 归输入层解释，所以写 `$HOME` / `$5` 会被当**任务引用**
  而报错（任务建不起来）。这与手输同一段文本的行为一致——不是模板引入的，但要知道（§7 第 4 条）。

### 3.5 加载时机

**每次命中按需读**，不做常驻缓存：模板是纯文本、极小；避免"文件改了不生效"和缓存失效
那一整类问题；与 `AGENTS.md` / skills 的处理一致。裸 `/prompt` 的目录扫描同样是按需。

### 3.6 代码位置

| 文件 | 内容 |
|---|---|
| `src/kernel/context/edc_prompts.{c,h}` | 解析、目录扫描、参数切分、替换（纯数据，无 shell 依赖） |
| `src/shell/edc_commands.c` | `/prompt` 分支：列表 / 载入 / 展开 / 交给 `edc_shell_execute` |
| `workspace/prompts/review.md` | 示例（随内嵌工作区发布） |
| `tests/test_prompts.c` | 单测：替换、切分、解析、越界、排序 |
| `tests/test_commands_prompt.c` | 集成：真的建出任务、管道、防递归、严格匹配 |

模块放在 kernel/context 而不是 shell：它是**资源加载**（与 `edc_skills.c` 同类），
而 `//src/shell:shell` 依赖 `//src/kernel:kernel`（反向依赖会成环）。
顺带：kernel **不能**用 `edc_shell_tokenize()`（它在 `//src/shell:shell` 里），
所以参数切分是模块自带的一小段代码，不是复用。

## 4. 不变式

1. **内置命令集不因用户内容而增长**：模板永远是 `/prompt` 的**参数**，
   永远不占用 `/` 之后的第一个 token。
2. **模板展开的结果是用户输入，不是命令**：不再进命令分发（不递归）。
3. **两个层级的记号分开**：模板层用 `$1`/`$@`/`${…}`（生态写法，也是我们的写法），
   输入层用 `{{…}}`（`{{LAST}}`/`{{<id>}}`/`{{SELF}}` = 任务引用）。
   谁也不能碰对方的记号——这一条取代了早先的"替换顺序"条款。

## 5. 验证（实际结果）

**`bazel clean` 之后 `bazel test //...`：78/78 绿**（1065 actions，全量重编）。

- `tests/test_prompts.c`：**58 条断言**。覆盖 front matter 有/无/带冒号/未闭合/空正文、
  越界名字（`../`、`a/b`、`.hidden`、空、含反引号）、列表排序与跳过、参数切分的引号与转义、
  §3.3 表格里的每一条替换（含多位 `${10}`、`$0`、未闭合的占位符、落单 `{`），
  以及**不变式 3 本身**：`$1`/`$@`/`${…}` 归模板层，`{{LAST}}`/`{{<id>}}` 归输入层。
  （本节是 2026-10-10 的历史记录；此后 `$` 的归属反转过，见顶部的"变更"。）
- `tests/test_commands_prompt.c`：**18 条断言**（照 `test_commands_task_new.c` 的手法：
  装假 session/scheduler + spy `send_llm`，驱动公开入口 `edc_commands_handler`）。
  覆盖：展开后的文本成为任务的输入、参数确实替换进去、未知名字不建任务、
  正文含 `|` 真的建出两个有依赖的任务、**正文以 `/` 开头仍是文本**、裸 `/prompt` 与
  `/promptx` 都不建任务。
- `tests/test_cmd_parse.c`：新增 `test_expand_vars_dollar_syntax`（**7 条断言**），把**输入层**
  的 `$` 规则钉住——之前**一条测试都没有**：`$$` = 前台任务（不是转义）、`$N`/`$NAME` = 任务输出、
  单引号是唯一挡得住的东西（且引号留在文本里）、`$` 后跟分隔符会被丢掉、结尾的 `$` 原样留下。

**五条变异，全部变红**（每次都是"改代码 → 跑测试 → 断言红 → 改回"）：

| 变异 | 红在哪 |
|---|---|
| 不认识的 `{{…}}` 丢掉而不是原样保留 | `{{0}}` / `{{weird}}` / `{{1` / `{1}` 四条 |
| `/prompt` 用宽松前缀匹配（`is_prefix`） | `/promptx` 那条——**它一开始没红**，因为测试太弱；为此在夹具里加了一个名叫 `x` 的模板，宽松匹配会把它当模板跑起来，差异才可观察 |
| 展开结果回到 `edc_commands_handler` 而不是 `edc_shell_execute` | "正文以 `/` 开头是输入不是命令"两条 |
| 取消位置参数替换（`{{N}}` 不认） | `{{1}}` / `{{2}}` / `{{3}}` / `{{10}}` 四条 |
| **把 `$1` 从输入层抢回来**（模板层重新吃 `$1`） | "`$1` is NOT ours" 那条——**不变式 3 的专用变异** |

> 第 2 条值得记一笔：**"测试通过"不等于"变异会红"**。第一版 `/promptx` 用例在宽松匹配下
> 也通过（因为回执内容不在断言范围内），是变异检查把它暴露出来的。

## 7. 待定 / 与原设计的偏离

**落地时偏离原设计的三处**（都写在这里，因为它们已经进了代码）：

1. **front matter 变成可选**。原设计是"缺 front matter 就跳过"，落地改成
   "没有 front matter 时 `description` 取正文第一非空行"。理由：一个只有正文的
   `review.md` 被静默拒绝太容易踩；pi 也是这个行为。
2. **front matter 按第一个 `:` 切**，不是 skills 那种每个 `:` 都切；并且去掉值两端
   成对的引号（`argument-hint: "[focus]"` → `[focus]`）。
3. **`/task fork` 现在必须有 desc**（旧行为靠 `--prompt` 凑 token，那条路没了）。

**仍然开着的口子**：

4. ~~字面 `$` 怎么写~~ → **已决：模板层改用 `{{…}}`，彻底不碰 `$`**（本文档 §3.3/§4 已按此改）。
   决策依据是那个撞车：输入层的 `$` 是**任务引用**（`$$`/`$N`/`$LAST`/`$NAME`，见 §5 的
   `test_expand_vars_dollar_syntax`），而模板层原来也用 `$1`，同一个拼法两个含义。
   - **残留（要知道，但不打算改）**：模板正文里如果写 `$HOME`、`$5` 这类，模板层不碰它，
     但它到输入层会被当**任务引用**——`$HOME: task not found`，任务**建不起来**。
     这不是模板的锅：**任何一行手输的文本**今天都是这个行为，模板只是继承了它。
     想要字面 `$`，目前没有可靠写法（单引号能挡住输入层，但引号会留在文本里）。
   - **模板里引用 shell 层面的任务输出**：**不支持**（模板是静态文本，见决策记录）；
     所以这不是"还没做"，是"不做"。
5. **模板正文长度上限**：正文会进上下文。像 skills 一样不限、靠上下文预算兜住，
   还是给一个明确上限？
6. **目录名**：`prompts/`。将来若要做"可执行的用户命令"，那是**另一件事**，另起名字。
