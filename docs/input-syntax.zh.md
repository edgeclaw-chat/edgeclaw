# 输入语法：新用户指南

你在 EdgeClaw 的输入框里打的每一行，只会落进**四种**里的一种。认出是哪一种只看**第一个字符** —— 这就是全部规则，记住它就不会有歧义。

| 行首 | 是什么 | 要不要引号 |
|---|---|---|
| `/` | **命令**（内建功能：切模型、建任务、跑模板…） | 不要 |
| `!` | **本地 shell 命令**（在你这台机器上跑一条命令，不经过模型；`/shell` 开关管不着它） | 不要 |
| `"` 或 `'` | **shell 语法**（一行字符串字面量，可以用 `\|` `;` `&` `>` `2>` 这些操作） | 要，而且是每一个字符串 |
| 其它任何字符 | **就是在跟模型说话** —— 一条消息，逐字节，什么都不解析 | 不要 |

**默认那一条最重要：你什么都不用管，直接说话就行。** shell 语法是默认**关闭**的，而且就算打开了，你不以引号或 `+` 开头，它也不会来碰你的话。`/` 和 `!` 不是 shell 语法，开关对它们无效 —— 用 `\!` 才把 `!cmd` 写成一条普通消息。

---

## 一、正常说话（99% 的时候）

直接打你的意思。**一整行就是一条任务**，模型看到的和你打的一模一样 —— 不切分、不改写、不需要引号。

```
帮我看看 src/ 里这个函数为什么慢
分析一下 A 和 B 两个方案的取舍
把 README 里的安装步骤重写一遍，保留 Windows 那节
```

哪怕你话里带 `|`、`>`、`引号`、"括号"，也**照旧是文本** —— 因为你这行不是以 `"` 或 `+` `!` 开头的：

```
比较 A|B 两种写法的开销          ← 一条任务，`|` 就是文本
条件是 x > 5 的时候报警          ← 一条任务，不是"重定向到文件 5"
```

> 这就是为什么普通对话不需要加引号：**判别发生在解析之前**。

---

## 二、命令（`/` 开头）

命令是内建功能，语法是它们自己的 —— 不需要引号（除了 `/task new "…" --bg` 那类**命令参数**要求描述带引号的情况）。

```
/help                       命令列表；/help <命令> 看某一条的细节
/whoami                     当前会话、模型、前台组、活动任务
/model                      列模型；/model <id> 切换
/connect                    引导式配置（provider / API key / model）
```

建任务、跑模板、跑技能：

```
/task new "写个播客脚本" --bg              建一条后台任务
/task new "审一下这段代码" -d task-1       等 task-1 跑完，并把它输出注入我的上下文
/task list                                看所有任务
/task stop                                停掉场上那条
/prompt review src/                       跑 prompts/review.md 这个模板，参数 src/
/skill git-commit 提交改动                直接跑 git-commit 这个技能
```

引号在命令语法里的唯一作用是**把描述和选项分开**：`/task new "写脚本" --bg` 对，`/task new 写脚本 --bg` 会被拒（描述没引号却带选项）。

## 三、shell 语法（先 `/shell on`）

**先打开它** —— 默认关闭：

```
/shell on
```

打开后，你可以用 shell 的操作来**组合**任务。规则只有一条：

> ### 这一行里，每一个字符串都要加引号；引号规则和 Python 一样

```
"先扫一遍" | "再修" | "写个报告"        管道：三条任务，后一条吃到前一条的输出
"跑测试" ; "提交"                      顺序：两条任务，只等不等输出
"跑完整测试" &                         后台：不占前台
"说 hello" > "out.md"                  重定向输出到文件
"任务" 2> "err.log"                    stderr 重定向
```

> 没有输入重定向：`<` 已经被删掉（`"任务" < "in.txt"` 会报错并指向 `@file`）。
> 要把文件内容喂给任务，用 `@` 引用：`看下 @src/main.c`、`@src/main.c#40-80`。
> `@` 不属于 shell 语法，`/shell off` 时同样可用；相对路径按会话的工作目录解析，
> 读取走沙箱与 `read_file` 同一个读函数，有 2000 行 / 64KB 单文件、128KB 单条消息的上限。


`+` 和 `!` 是另外两个 sigil（它们自己就宣告"这是 shell 行"）：

```
+"修复登录超时"                        新开一个组来放这条任务（隐含：不和当前对话混在一起）
+"审一下这段代码" &                    新组 + 后台
+"排查" -d task-1                       新组 + 依赖 task-1
!git status                            本机跑一条 shell 命令（不调模型、不花 token）
!!                                     再跑这条会话上一条 `!` 命令
```

### 为什么必须加引号

因为不加就分不清"你文本里的符号"和"你要的操作"：

```
现在新建任务A|B          ← 你这是想要  "现在新建任务A" | "B"  还是  一条文本 "现在新建任务A|B"?
```

所以规矩是：**要管道，就把两边都引起来；想让符号当文本，就把它也引进去。**

```
"现在新建任务A" | "B"      两条任务（管道）
"现在新建任务A|B"          一条任务，文本里就带这个 |
```

注意上面这两行**都以引号开头** —— 这就是它们被当作 shell 语法的原因。

### 引号之后只能跟选项

引号闭合之后是**选项区**（`-d <id>`、`-g <group>`、`2>`…）。**`--bg` 不在其中** —— shell 行里后台只有链尾 `&` 一种拼法（`--bg` 是命令层的参数）。别的字出现在那里会**报错，而不是被丢掉**：

```
"hello" and more      ← 报错：`and` 不是选项。要么写成 "hello and more"，要么去掉。
```

（这是故意的：以前它会把 `hello` 当任务、把 `and more` 静默扔掉。）

### 引号的写法（和 Python 一致）

```
"双引号"              里面可以写 {{LAST}} 这类引用，会被替换
'单引号'              原文，什么都不替换
"""
粘贴进来的
多行文本
"""                   三引号跨行 —— 粘贴长文本用这个
```

**想写一个以 `+` 或 `@` 开头的描述，靠引号，没有转义符**：

```
"+1 issue is still open"        ← 一个当文本用的 `+`
"@alice please take a look"     ← 一个当文本用的 `@`
```

### 关掉它

```
/shell off
```

关掉后一切都是消息（引号也只是普通字符）。要看当前状态就跑不带参数的 `/shell` —— 页脚里没有这一格。

---

## 四、三条最容易踩的

1. **以引号开头的普通消息会被当成 shell 行。** 你本来想发 `"这个问题" 帮我改` —— 请写成 `"这个问题，帮我改"`（整段进引号）或干脆不加引号。
2. **`+/…` 不存在。** shell 语法和命令语法**不混用**：要新组就用 `+"描述"`，命令要新组就用 `/task new "描述" --new-group`。
3. **shell 行里少了一个引号** → 整行被拒（会告诉你哪里不对），不会静默猜。

## 五、小抄

```
帮我看看这段代码                 消息（一条任务）
比较 A|B 的写法                  消息（`|` 是文本）
/help                            命令

/shell on                        打开 shell 语法
"先扫" | "再修"                  管道
"跑测试" ; "提交"                顺序
"跑测试" &                       后台
"说 hi" > "out.md"               重定向
+"新话题的任务"                  新组
+"新话题" &                      新组 + 后台
!git status                      本机命令（不花 token）
/shell off                       关掉
```

## 六、还没做的（先别试）

- **`@文件` 引用**：`@` 是留给文件引用的，但功能还没落地。现在以 `@` 开头的 shell 行会告诉你"`@` 不再用来开新组了"。
- **`/group new`**：目前开一个空的工作组做不到，所以 `/prompt`、`/skill` 建的任务总是进**当前**组（`--new-group` 只有 `/task new` 有）。
