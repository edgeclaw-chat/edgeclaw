# timeout：对端**连上却永不回** —— 在途操作必须有一个内核保证的出口
#
# 假 LLM 把这个应答压后 60s，**远超整个运行时长** —— 所以对端在这次运行里
# 等于**死了**（不是"慢"）。配合 `--env EDGECLAW_HTTPS_TIMEOUT_MS=3000` 就
# 能在几秒内跑到期限，不必真等默认的两分钟。
#
# 期望（改动后）：约 3s 时期限到 → 走**和失败完全相同**的路（ERROR + CLOSE）
# → 任务以 ERROR 收场。
# 改动前：状态停在 LLM_PROCESSING —— 在对端已死的情况下它**没有任何出口**，
# 只能等进程被杀。这正是要修的洞。

wait 1500

# 触发 LLM 请求（进入在途；此后对端不会回）
send hello there\n

# 等到期限之后（3s）、但远早于那个 60s
wait 6000
wait 1500
